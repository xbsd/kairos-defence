# Phase 10: User guide, one-pager and rollback guide, plan

## Goal

Documentation that a new user, a presenter and a maintainer can each use without reading the spec
(`docs/phases/PHASE_10.md`): a complete user guide with real screenshots captured from the running
app by a repeatable Playwright spec, a one-page summary, a rollback guide, a root README that links
everything, and current package READMEs. The phase passes when `make check && npm --prefix web run
build && make e2e && python3 scripts/check_docs.py` all pass and the screenshots in
`docs/guide/img/` come from that run's `make e2e`.

## Inputs read

- `docs/phases/PHASE_10.md` (the phase block), CLAUDE.md, SPEC §1, §2, §16.4, §17, §18, §19, §23,
  Appendix B; `docs/DEMO.md` (phase 9), `docs/AUTOPILOT.md`, `docs/phases/INDEX.md`, every
  `docs/phases/phase-*/REPORT.md` (phase 9's newest), `README.md`, every package README.
- `scripts/check_docs.py` (the documentation gate: the five documents exist; every local link
  resolves; the guide has ≥ 3000 words outside code blocks, mentions "Live watch", "Match
  explainer", "Case board", "Swarm view", "Evidence", "Shift delta", "Director",
  "kairos-defense", "make demo", "MCP", "Troubleshooting", "Glossary" and "synthetic", and embeds
  ≥ 10 distinct PNGs of ≥ 20 kB; the one-pager has 250–700 words and an image; the rollback guide
  names `phase-04-done` … `phase-10-done`, "autopilot-start" and "git revert"; the README links
  `docs/USER_GUIDE.md`, `docs/ONE_PAGER.md`, `docs/ROLLBACK.md` and `docs/DEMO.md`).
- `docs/phases/gates.json` phase 10: `npm --prefix web run build`, `make e2e`,
  `python3 scripts/check_docs.py` (plus `make check`).
- `web/e2e/helpers.ts`, `director.spec.ts`, `pages8.spec.ts`, `swarm.spec.ts` (patterns for
  driving the real app and waiting for each state).

## Assumptions and decisions

Recorded in `docs/DECISIONS.md` during the build.

- B1 (screenshot spec): `web/e2e/guide.spec.ts`, run by `make e2e` with the existing Playwright
  `webServer` (scratch ledger and exports, port 8765), writes PNGs to `docs/guide/img/` (path from
  `web/`: `../docs/guide/img`). Every shot first waits for the element that proves its state
  (ghost count 3, lens curves, forecast label, recall overlay, case graph, diff group, evidence
  verify passed, swarm ghost, eval tile, delta group, shortcuts dialog), then lets fades settle
  (1.6 s). No mock data, no image editing, no placeholder states ("Loading" never captured).
- B2 (shot list, 1920 × 1080 unless noted): `live-watch-t090`, `live-watch-t090-1440x900` (the
  layout at the smaller size), `live-watch-t120`, `director-01-detection`,
  `director-02-recording`, `director-03-recognition`, `director-04-time-warp`,
  `director-05-forecast`, `director-06-recall`, `director-07-known`, `director-08-evidence`,
  `director-09-encore` (the nine Director beats at 5×), `explainer`, `case-board-known-then`,
  `case-board-known-now`, `evidence`, `shift-delta`, `eval`, `swarm-view`, `shortcuts`: 20
  images, all distinct. The hero image of the one-pager and the README is `live-watch-t120`.
- B3 (CLI reference): generated by hand from `--help` with one real example output per command
  (copied from this machine's run, trimmed); `tests/unit/test_docs.py` checks every command in the
  Typer app (and the `memory` subcommands) appears as `kairos-defense <name>` in the guide.
- B4 (docs tests): `tests/unit/test_docs.py` parses Markdown links and images with the same
  pattern as `check_docs.py` and checks every relative target in `README.md`,
  `docs/USER_GUIDE.md`, `docs/ONE_PAGER.md` and `docs/ROLLBACK.md` exists (URLs and in-page
  anchors skipped).
- B5 (screenshots in git): `docs/guide/img/*.png` are committed; the gate's `make e2e` rewrites
  them and `cloud_gate.py close` commits the rewritten files, so the committed images are the
  gate run's.
- B6 (tags): the rollback guide names `phase-09-done` and `phase-10-done`, which
  `cloud_gate.py close` creates; phases 0–3 have no tag (their commits are named instead).

## Work breakdown

1. `web/e2e/guide.spec.ts` (B1, B2): Live watch is played at 2× to the target second (a small
   overshoot on a slow machine, D-154) and paused; Director runs at 5× and pauses on each beat
   with Space before its shot, as `director.spec.ts` does. Run it alone, review every image
   against §17 (alignment, overlap, contrast, glow restraint, legibility at the size shown, no
   placeholder or loading state), fix what is wrong (in the spec's waits, or in the UI if a real
   defect shows), and log findings and fixes in `REPORT.md` and the PROGRESS.md session log.
2. `docs/USER_GUIDE.md`: the twelve sections of PHASE_10.md, in order, with the images.
3. `docs/ONE_PAGER.md` (250–700 words, the hero image), `docs/ROLLBACK.md`.
4. Root `README.md`: what it is, the status table, quick start, links to the guide, the
   one-pager, the rollback guide, `docs/DEMO.md`, `docs/AUTOPILOT.md` and every package README.
5. Package READMEs: check each of the 13 package READMEs (`src/kairos_defense/README.md` and the
   12 sub-packages, `agent` included) and `web/README.md` for the template's sections and a
   changelog entry for the last phase that touched the package; fix any that lag the code.
   `web/README.md` gains the guide spec; `src/kairos_defense/README.md` notes the docs test.
6. `tests/unit/test_docs.py`.
7. Exit check, `EXIT_CHECK.md`, `REPORT.md`, PROGRESS.md session log, DECISIONS.md; commit
   `phase 10: user guide, one-pager and rollback guide`.

## Risks and mitigations

- Slow machine (software WebGL, 4 vCPU): waits are on state, not time; the 1.6 s settle is fixed.
- Images identical across runs would still be distinct from each other; check_docs only requires
  distinct images within the guide.
- Word count: the guide covers twelve sections; the count is checked before the commit.

## Out of scope

Code changes beyond fixes the screenshot review demands; new features.
